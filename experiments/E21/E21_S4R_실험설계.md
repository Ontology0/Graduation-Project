# E21 · 4-State Single-Prefill Router (S4R)
## 해결책 — 박세령 4-state 판독에서 출발하는 행동 라우팅

**작성일:** 2026-11-04 · **버전:** S4R-1.0.0 · **상태:** 구현 및 CPU 검증 완료, 실제 Llama 8B GPU 성능 미측정.

핵심 파일은 `E21_4State_SinglePrefill_Router.ipynb`이다. 모든 구현이 읽을 수 있는 코드 셀에 들어 있으므로 부속 Python 파일을 Colab에 업로드할 필요가 없다. 원본 데이터는 기존 Drive의 확인된 파일 ID로 자동 확보한다. 원본 노트북과 과거 실험 결과는 변경하지 않는다.

## 1. 문제상황 — 무엇을 발전시키는가

이번 개발의 중심은 Packed 후보 선택이 아니라 **4-state를 읽고 같은 입력의 개입 행동을 결정하는 라우터**다. 이미 생성된 A/B 답변, 추가 closed-book 경로, 후보별 첫 토큰 확률은 온라인 라우터 입력에서 제외했다.

소스 조사에서 두 판독기를 구분했다. E16 심사 대응 노트북과 제출 논문의 원형은 역할별 top-4 헤드의 합집합을 만든 뒤, 선택된 헤드의 **마지막 프롬프트 위치 벡터(HEAD_LAST)**를 연결하여 4-state LR을 학습한다. 반면 E17의 vector LR은 `HQ + (HL−HQ) + C_MASS`를 연결한 확장 특징을 사용한다. 서로 같은 판독기라고 부르지 않는다.

E21 주 방법은 **E16의 특징 정의**를 사용한다. E14/E17의 질문 단위 분할, E14의 instruction contrast 개입 벡터 구성, E19의 prefill-only 개입 스케줄을 명시적으로 조합한다. 과거 노트북 전체를 그대로 재현하는 실험이 아니라, 그 구성요소를 통제해 라우팅을 검증하는 새 후속 실험이다.

## 2. 원인 — 상태 판독과 좋은 행동 선택은 다르다

`K−C+` 판독은 문맥을 활용해야 할 가능성을 알리지만, 그 자체가 추가 accept 개입으로 정답이 늘어난다는 뜻은 아니다. Base가 이미 문맥을 이용해 맞힐 때는 no-op이 더 안전할 수 있다. 마찬가지로 retain 개입도 모든 `K+C−` 입력을 고치지는 못한다.

기존 단순 규칙은 그대로 대조군으로 남긴다.

| 예측 상태 | 단순 규칙 행동 |
|---|---|
| K+C+ | No-op |
| K+C− | Retain |
| K−C− | No-op |
| K−C+ | Accept |

`K−`는 관련 지식의 완전한 부재가 아니라 지정된 closed-book 응답의 관측 정오다. conflict 역할의 `K XOR C`도 의미적 모순을 직접 판정한 라벨과 구분한다.

## 3. 해결책 — 원형 판독 + 회복·손실 행동 라우터

### 3.1 원형 판독을 유지한다

오프라인 헤드 선발에서 memory는 질문 끝 헤드 벡터의 크기와 K, context는 문맥 어텐션 질량과 C, conflict는 두 위치 벡터의 상대 변화량과 K XOR C를 대응시킨다. 각 역할의 AUROC를 `max(AUC, 1−AUC)`로 변환해 top-4를 고르고 합집합을 사용한다. 동점은 작은 헤드 ID를 우선한다.

최종 LR 입력은 선택된 HEAD_LAST 벡터뿐이며, 표준화·LR은 fit 질문으로만 학습한다. **온라인 실행에서는 HQ·C_MASS나 별도 질문-only 추론을 요구하지 않는다.** 어텐션 헤드 수나 성능은 새 실행 결과로 기록하며, 과거 7–10개나 과거 F1을 이번 결과로 복사하지 않는다.

### 3.2 행동의 회복과 손상을 따로 학습한다

오프라인에서 각 훈련 입력의 no-op, retain, accept 답변을 생성해 비교한다. 각 개입 행동 `a`에 대해 다음 전이 라벨을 만든다.

- Gain: Base 오답 → 개입 정답.
- Harm: Base 정답 → 개입 오답.
- Unchanged: 정답 여부 변화 없음. 문자열 동일 여부와는 다르다.

라우터 입력은 **예측한 네 상태 확률 p4**이며, 행동별 전이 확률을 작은 LR로 예측한다. 주 점수는 다음과 같다.

`U(a | p4) = P(Gain | p4, a) − 2 × P(Harm | p4, a)`

계수 2, LR 정규화, 최소 관측 회복 수 3, 후보 임계값 그리드는 실행 전에 고정한 설계값이다. 검증으로 증명된 최적값 또는 확률 보정 보증으로 주장하지 않는다. 희소 사건은 smoothing을 적용하고, 관측 회복이 부족한 행동은 비활성화한다.

정책은 예측 손상과 효용 조건을 통과하는 행동만 허용하며, 불확실하거나 이득이 없으면 no-op을 선택한다. 행동명은 `retain / accept / no-op`이지만, 라우터가 상태를 정답처럼 취급하거나 상태별 강제 규칙만 수행하는 것은 아니다.

### 3.3 같은 prefill 안에서 결정하고 적용한다

`질문+문맥 → L13 선택 헤드 판독 → p4 → 행동 선택 → L14–18 마지막 프롬프트 토큰 개입 → KV cache를 이어받아 답변 생성`

구현은 일반적인 왼쪽 패딩 배치를 사용한다. 한 질문을 A/B 두 경로로 복제하지 않는다. L13보다 앞선 층을 다시 실행하지 않고, 첫 답변 토큰의 로짓이 나오기 전에 개입 행동을 결정한다. decode에서는 재판독이나 추가 스티어링을 하지 않는다.

**one-pass의 의미:** 하나의 contextual prefill과 하나의 자기회귀 생성 경로. 답변 전체를 모델 forward 1회로 만든다는 뜻은 아니다. 토큰 생성에는 KV cache를 사용하는 반복 forward가 필요하다.

### 3.4 벡터를 고정해 라우팅 효과를 분리한다

E14와 같은 방식으로 fit의 64질문 및 C± 입력에서 context-reliance 지시와 memory-reliance 지시의 residual contrast를 오프라인 추출한다. 질문-only 답변이나 Packed A/B contrast를 사용하지 않는다. 동일 벡터에 retain은 −0.5, accept는 +0.5를 적용하고, L14–18 각 층의 이동량을 해당 residual norm의 5% 이내로 제한한다.

제안 이동량과 BF16 반올림 후 실제 이동량은 각각 기록한다. 한 정책만 더 큰 강도를 쓰거나, 외부 테스트에서 벡터를 다시 고르지 않는다. **이 단계에서는 E19 성공 Prototype을 새로 최적화하지 않는다.** 이후 별도 actuator 비교를 할 수 있지만, 이번 주 비교에서는 라우터 변경 효과를 고립시킨다.

## 4. 분할 및 누출 방지

| 구간 | 질문 | C± 입력 | 사용 |
|---|---:|---:|---|
| fit | 366 | 732 | 원형 헤드 선발·LR 학습, instruction 벡터 추출, OOF 행동 라우터 학습 |
| utility_fit | 61 | 122 | 판독기가 보지 않은 질문의 행동 라우터 학습 |
| policy_cal | 62 | 124 | 라우팅 임계값 선택, 보존 점검 |
| test | 123 | 246 | 잠긴 정책으로 p8s 평가 |

fit 질문의 라우터 학습 특징은 5-fold question-wise OOF 확률이다. **각 내부 fold마다 헤드 선발·표준화·LR을 다시 학습한다.** utility_fit은 최종 판독기의 미학습 질문이므로 최종 판독 확률을 사용한다. 합계 427질문의 행동 결과를 학습하며, 임계값은 별도 62질문에서 정한다.

이것은 20% 라벨 예산 재현이 아니다. 또한 QA 최종 성능의 5-fold 평균 실험이 아니라 fold-0 후속 실험이다. OOF 판독기와 전체 fit 판독기의 예측 분포 차이는 완전히 제거되지 않으며 한계로 기록한다.

임계값 선택은 policy_cal에서 C+ 및 K−C+의 Base 정답 손실이 0이고, 전체 정답 순증가가 양수인 정책만 허용한다. 적절한 정책이 없으면 no-op으로 잠그고 전체 그리드를 저장한다. **검증셋 손실 0은 테스트 보존을 보장하지 않는다.** 정책이 전부 no-op이면 라우팅 개선 성공으로 보고하지 않는다.

## 5. 비교 방법 — 같은 개입 수단, 다른 결정

| 방법 | 확인할 기여 |
|---|---|
| Base | 무개입 답변 기준 |
| Always retain / Always accept | 상태에 관계없이 고정 개입하는 효과 |
| 4state rule | 예측 상태를 고정 규칙으로 행동에 대응 |
| 4state confidence | 단순 규칙에 신뢰도 임계값 추가 |
| **S4R gain–harm** | **p4로 실제 회복·손상을 예측하는 라우팅** |
| K-only / C-only / Conflict-only | 네 상태 조합 정보가 각 단일 축보다 유용한지 |
| Action Oracle | 정답을 알고 세 행동 중 고르는 진단용 상한 |
| State Oracle rule | 실제 상태에 단순 규칙을 적용한 진단값. 상한은 아님 |

주 방법은 test를 보기 전 `S4R_gain_harm`으로 고정한다. 비교 결과에서 가장 높은 test 방법을 다시 주 방법으로 선정하지 않는다. 주 방법과 각 대조군의 질문 묶음 대응 신뢰구간을 저장하되, 다중 비교가 보정된 통계적 확증이라고 주장하지 않는다.

## 6. 평가 및 효과 판정

외부 데이터는 NQ-Swap corpus subset 앞 1,000개 원본 ID와 ConFiQA 질문 중복 제거 후 앞 1,000개를 사용하며 각각 C±를 보존한다. 이는 E20의 표본 구성에 맞춘 후속 비교이고, E19의 SHA 순서 500개 표본과 같지 않다. 최대 생성 192토큰을 포함한 모든 조건으로 Base부터 다시 생성하므로 과거 E20의 256토큰 수치와 그대로 이어 붙이지 않는다.

각 정책의 답변은 **그 정책을 실제로 실행해서 생성**한다. 사후 후보 표로 합성하지 않는다. 원본 K/C 정답은 온라인 입력 객체에 들어갈 수 없고, 현재 standalone closed-book은 모든 contextual 출력이 나온 뒤 평가용 K를 붙이는 용도로만 실행한다. 과거 corrected K와 현재 측정 K는 별도 보고한다.

최종 지표는 전체·C±·4-state별 answer-EM, raw-EM, kept/lost/gained, 기존 정답 보존율, 개입률이다. answer-EM은 기존 방식대로 첫 답변을 추출하므로 완전한 raw string EM과 구분한다. NQ의 서로 다른 ID가 같은 질문을 공유할 수 있어 신뢰구간은 정규화 질문 문자열로 묶는다. 원본 ID 가중 평균과 고유 질문 수를 함께 기록한다. train/cal과 겹치는 질문을 제외한 공통 보조 결과도 저장한다.

원패스 감사 로그는 각 실제 온라인 실행의 prefill 횟수, 라우터 호출 횟수, decode forward 수, decode 개입 수, 개입 순서, 토큰 수, 이동량을 기록한다. Base와 새 라우터의 batch=1 지연시간은 warm-up 뒤 반복 측정한다. 라우터 계산 비용은 포함하지만 학습/진단용 여러 실행을 배포 비용처럼 섞지 않는다. 속도 향상은 측정 전 주장하지 않는다.

해석은 세 경우를 분리한다. Action Oracle에도 개선 여지가 작으면 현재 행동 집합의 효과가 약한 것이고, Oracle과 실제 라우터의 차이가 크면 행동 선택이 병목이다. 상태 규칙보다 새 라우터가 개선되면 상태에서 행동으로 연결하는 정책의 추가 효과를 논의할 수 있다. 단, 통계적 불확실성과 C+ 손상을 함께 보고해야 한다.

## 8. 검증 범위와 남은 한계

배포본은 출력이 비어 있다. CPU 단위 테스트와 작은 PyTorch causal-attention 대역 모델에서 실제 forward hook/KV 재사용 경로를 검증했다. **대역 모델은 Llama가 아니며, 이 결과는 연구 정확도나 A100 성능 수치가 아니다.** 실제 transformers 4.57.1/Llama-3.1-8B 조합의 GPU 실행은 아직 수행하지 않았다. 노트북은 GPU에서 no-op 동일성, 판독 확률 일치, read-before-write, 실제 라우팅과 동일 강제 행동의 출력 일치 여부를 추가 확인하고 실패 시 중단한다.

현재 벤치마크들은 연구 과정에서 이미 여러 번 확인됐다. 이번 실행 안에서 테스트 재보정을 막더라도 새로운 blind test가 되는 것은 아니다. 논문의 확증적 주장에는 사전에 잠근 추가 데이터/모델/시드 검증이 필요하다. 62질문 보정 표본은 작고, strict preservation으로 유효한 정책을 찾지 못할 수 있다. 모든 방법이 no-op이 되는 결과도 숨기지 않는다.

**검증할 논문 문장:** “단일 질문–문맥 prefill의 선택 헤드에서 K/C 4-state를 판독하고, 그 상태 신호로 개입의 회복·손상 가능성을 추정하여 동일 추론 경로의 retain·accept·no-op을 선택한다.” 아직 성능 우위나 최초성을 확정한 문장은 아니다.
