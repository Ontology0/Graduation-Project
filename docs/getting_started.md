# 처음 읽는 안내

> 목적: 낯선 실험 번호보다 문제와 선택을 먼저 이해하고, 설치 없이 첫 결과를 확인하기

## 1. 책을 펼쳐 놓고 답하는 모델

LLM이 외부 문서를 보고 질문에 답하는 상황을 생각해 보세요. 문서를 읽기 전부터 알고 있던 답과 문서가 제시하는 답이 다를 수 있습니다.

- **문서가 틀리고 모델의 기억이 맞으면:** 문서에 끌려가던 답을 바로잡아야 합니다.
- **문서가 맞고 모델의 기억이 틀리면:** 기억을 강화하는 개입이 오히려 정답을 망칠 수 있습니다.
- **둘 다 틀리면:** 둘 중 하나를 선택하는 것만으로 정답이 나오지는 않습니다.

그래서 질문은 ‘모델이 아는가?’에 머물지 않습니다. **‘이 입력에 개입하면 실제로 답이 더 좋아지는가?’**가 현재 연구의 중심입니다.

## 2. 읽는 신호·개입·선택을 구분하기

| 구분 | 하는 일 | 혼동하지 않을 것 |
|---|---|---|
| 내부 신호 분석 | 어텐션 헤드·은닉 표현 등에서 상태와 개입 이득에 관련된 정보를 읽음 | 잘 읽힌다고 답변도 자동으로 좋아지는 것은 아님 |
| Steering | 모델 가중치는 그대로 두고 추론 중 내부 활성값에 방향을 더하는 등의 조절 | 모든 실험이 같은 헤드를 직접 조작하는 것은 아님 |
| Routing | 예측한 이득에 따라 개입하지 않거나, 유지·수용 방향 및 강도를 고름 | 모델 전체를 재학습하지 않아도 Router 자체는 학습할 수 있음 |
| Packed | 문맥을 본 분기와 보지 않은 분기를 한 입력 처리 호출에 담고 분기를 선택 | Routing의 행동 선택과 다른 규칙; 한 호출이 같은 계산량을 뜻하지 않음 |

대표적으로 A1은 L7/L13에서 신호를 읽고 early/late 개입 행동을 비교합니다. 늦은 개입은 L14–18 블록 출력에 적용하는 설정입니다. **신호를 읽는 위치와 조절하는 위치를 구분**해서 노트북을 읽으세요.

One-pass Routing은 실제 추론 중에 신호를 읽고 행동을 선택하는 경로입니다. [온라인 Router 노트북](../experiments/presentation/E15_Online_StrongRetain_UtilityRouter.ipynb)이 있지만, [A1](../experiments/A1/A1_staged_routing.ipynb)의 저장 결과 조회 평가와는 실행 방식·프롬프트가 다릅니다. A1 점수를 그대로 온라인 방식의 실측 성능·속도로 옮기지 않습니다.

## 3. 설치 없이 첫 결과 확인하기

1. [A1 정책 CSV](../experiments/A1/%5Bresult%5DA1_staged_routing/A1_policies.csv)를 엽니다.
2. 아래 세 행의 `EM`을 비교합니다. CSV는 0–1 비율이고 아래 표는 %입니다.
3. [A1 summary](../experiments/A1/%5Bresult%5DA1_staged_routing/A1_summary.json)의 신뢰구간까지 함께 읽습니다.

| CSV의 정책 | 쉬운 뜻 | P8S 정답률 |
|---|---|---:|
| `no-op` | 개입하지 않음 | 53.10% |
| `always: late_ret_r0.06 (동결)` | 모두에게 같은 늦은 retain 개입 | 59.97% |
| `late-only (L13, 이득 예측)` | L13 신호로 행동별 이득을 예측해 선택 | 60.78% |

숫자만 보면 Router가 가장 높지만, Always 대비 차이는 **+0.82%p [95% CI: −0.49, +2.21]**로 유의한 우위가 검출되지 않았습니다. `oracle` 행은 정답을 아는 가상의 선택 상한이므로 실제 사용 가능한 방법의 성능에 포함하지 않습니다.

이 결과는 P8S 612질문·1,224입력의 저장 행동 결과를 이용한 평가입니다. 외부 ConFiQA 결과나 신규 모델 실행 결과가 아닙니다. 이처럼 **결과 → 조건 → 한계** 순으로 확인하면 됩니다.

## 5. 결과표의 최소 용어

| 용어 | 뜻 |
|---|---|
| P8S | 팀의 PopQA 기반 개발용 실험셋; 현재 비교는 612질문에 C± 두 입력씩 사용 |
| K+ / K− | 문맥 없이 생성한 답이 채점 기준상 맞음 / 틀림; 모델의 모든 지식 유무를 뜻하지 않음 |
| C+ / C− | 정답을 포함한 문맥 / 정답을 다른 답으로 치환한 문맥 |
| EM | 생성한 답과 정답의 일치율; 채점 정규화·정답 별칭 조건을 함께 확인 |
| C+ 손상 | 올바른 문맥을 활용하던 성능이 개입 후 낮아지는 현상 |
| C+ 비열등 | 성능 저하가 사전에 정한 허용 범위를 넘지 않는다는 통계 기준; 완전 무손상·성능 향상을 뜻하지 않음 |
| prefill | 답변 토큰을 생성하기 전에 입력 프롬프트를 처리하는 단계 |
| ablation | 구성 요소를 빼거나 바꿔 무엇이 결과에 기여하는지 비교하는 분석 |

외부 평가에서는 C± 모두 **원래 사실 정답**으로 채점했습니다. 잘못된 문맥이라도 충실히 따르는 능력을 평가한 원 논문 점수와 직접 순위를 비교하지 않습니다.

## 새 참여자의 작업 순서

1. [연구 계획](research_plan.md)에서 담당할 질문을 정하고, [관련 회의록](README.md#회의와-원문-자료)의 결정과 미완료 과제를 확인합니다.
2. [실험 안내의 입력 조건](../experiments/README.md#실행에-필요한-입력)을 확인합니다. 원본 데이터·hidden cache·manifest는 일부 별도 공유이며, 코드가 있다고 입력까지 모두 포함된 것은 아닙니다.
3. 해당 노트북의 설치 셀·모델 revision·프롬프트·레이어 번호·라벨·seed/fold를 확인한 뒤 필요한 런타임을 준비합니다. 기존 결과는 새 실행 폴더와 분리합니다.
4. 모델 실행 시 모델 접근 권한·GPU가 필요합니다. A1 등 저장 자료 분석은 선행 입력이 준비되면 CPU로 가능합니다. 초기 RAG 설치 파일은 `legacy/`에 있으며, 현재 실험의 환경은 각 노트북을 기준으로 준비합니다.
5. 변경한 질문·설정·결과·한계를 함께 기록하고 [기여 규칙](../CONTRIBUTING.md)에 따라 리뷰를 요청합니다. 공개 전 토큰·개인정보·심사 중 자료 포함 여부를 확인합니다.

[SOTA 비교 코드](../SOTA/README.md)는 import 배치와 미구현 방법 정리가 남아 있습니다. 현재는 완성된 통합 패키지나 서비스 데모가 아니라 **진행 중인 연구 코드 저장소**입니다.
