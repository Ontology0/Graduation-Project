### 💡 논의 내용

**1. Routing 중심의 연구 방향 정리**
- Always Steering은 잘못된 문맥의 영향을 줄이는 과정에서 올바른 문맥을 활용하는 성능도 함께 낮추는 문제가 있으므로, 학습 기반 Routing을 중심으로 연구를 발전시키기로 함
- `no operation`, 여러 강도의 `retain`, `accept` 등 Router가 선택할 행동의 구성을 다시 검토하기로 함
- 개입 강도(ρ)를 임의로 정하지 않고, 다양한 설정을 비교하여 안정적인 성능이 나타나는 구간을 찾기로 함
- 행동의 종류와 개입 강도를 선택한 이유를 실험 결과뿐 아니라 논리적으로 설명할 수 있도록 분석하기로 함

**2. One-pass Router 고도화**
- 학습 단계에서는 여러 개입 행동의 결과를 사용하되, 실제 추론에서는 내부 신호만으로 행동을 한 번에 선택하는 구조를 목표로 함
- attention head의 hidden state, 중간 레이어의 entropy 등 추가 내부 신호를 Router 입력으로 활용할 수 있는지 확인하기로 함
- 기존 Router, One-pass Router, Router를 사용하지 않는 구성의 답변 성능과 추론 비용을 비교하기로 함
- 최종 메소드를 확정한 뒤 팀원별 구현 결과를 교차 확인하여 구현 차이로 인한 성능 편차를 점검하기로 함

**3. 프롬프트 기반 확신도와 Steering의 통합**
- 문맥이 있는 분기와 없는 분기의 첫 토큰 및 로그 확률을 비교하는 방법은 성능 향상 가능성이 있으나, 데이터셋에 따라 올바른 문맥을 활용하는 성능이 하락할 수 있음을 확인함
- 해당 방법은 선택적 구성 요소로 두고, 포함한 경우와 제외한 경우의 성능 및 추론 비용을 함께 제시하기로 함
- 첫 토큰이 같을 때 특정 분기를 선택하는 이유와 두 분기의 로그 확률을 비교하는 기준이 왜 효과적인지 분석하기로 함

**4. 외부 벤치마크와 논문 구성**
- 자체 P8S 데이터셋에 기존 방법을 모두 재구현하기보다, 기존 연구에서 사용한 데이터셋에 팀의 최종 방법을 적용하는 방향을 우선하기로 함
- 비교 방법별 hyperparameter를 공정하게 조정하고 held-out 평가를 통해 기존 연구 대비 개선 폭을 확인하기로 함
- 지금까지 수행한 실험에서 각 구성 요소가 필요해진 배경을 보여주는 observation과 분석 결과를 정리하기로 함
- 산재한 Colab 파일과 실험 결과를 정리하여 재현 가능한 형태로 통합하기로 함

**5. 4-state 판별 논문 제출**
- Steering 연구와 별도로, attention head 기반 지식–문맥 4-state 판별과 소량 라벨 조건의 성능을 중심으로 논문을 정리함
- 논문 파일과 제출 정보를 최종 점검한 뒤 심사용 논문 제출을 완료함
- 추후 최종본 제출 전에도 논문 파일과 제출 페이지를 다시 확인하기로 함

### ✅ 결정 사항
- 후속 연구는 Always Steering보다 Routing과 One-pass Routing 고도화에 집중함
- Router의 행동 구성과 개입 강도(ρ)에 대한 탐색 및 근거 분석을 수행함
- 프롬프트 기반 확신도는 선택적 구성 요소로 두고 성능과 계산 비용의 trade-off를 비교함
- 최종 방법을 확정한 뒤 기존 연구의 벤치마크에서 공정한 비교 실험을 진행함
- 기존 실험 결과와 파일을 정리하고 각 구성 요소의 필요성을 설명할 observation 및 분석을 보완함
- 4-state 판별 논문은 심사용 제출을 완료함
