01

검색한 문서도, 모델의 기억도 틀릴 수 있다

WHY

문서를 무조건 따르거나 기억을 무조건 강화하는 대신, 상황에 맞게 답변 방식을 바꿔야 한다.

상황 A · 문서에 오류가 있을 때

“호주의 수도는?”

모델의 기억

캔버라 정답

≠

오류가 있는 문서

시드니 오답

문서보다 기존 지식을 유지하는 것이 유리하다.

상황 B · 기억한 정보가 오래됐을 때

“오늘 도서관은 몇 시에 닫나요?”

모델의 기억

18시 오답

≠

최신 운영 공지

20시 정답

기억보다 올바른 문서를 수용하는 것이 유리하다.

이해를 돕기 위한 가상 입력 예시이며 실제 평가 문항이 아니다. 추론 시에는 정답 여부를 알려주지 않는다.

02

내부 신호를 읽고, 필요한 개입만 선택한다

HOW

Routing은 개입을 고르고, Steering은 내부 활성값을 조절한다.

ONE-PASS ROUTING

One-pass는 추론 중간에 신호를 읽고 이후 개입을 결정한다. 구현 예: L13 읽기 → L14–18 개입. 선택기(Router)는 별도로 학습한다.

별도로 구현·분석한 접근

답변 비교 · Packed

문서를 본 답 A ↔ 문서 없이 낸 답 B → 분기 선택

두 경로를 한 입력 처리에 담아 비교한다. Routing과는 별도로 구현·평가한 접근이다.

03

정답률 개선과 ‘맞히던 답 보호’를 함께 검증했다

EVIDENCE

ConFiQA-QA · 1,000질문 / 2,000입력
사실 정답과의 정확 일치율(EM)로 평가 · 변화량 단위: %p

개입 전 정답률  51.65%

① 전체 정답률은 얼마나 좋아졌나?

개입 전 대비 변화 · 점: 평균, 선: 95% 신뢰구간

② 맞는 문서를 줬을 때는 괜찮을까?

올바른 문맥(C+)에서의 변화 · 왼쪽은 성능 손실

Routing은 전체 성능 개선과 C+ 허용 손실 기준을 충족.다만 C+ 개선이 입증됐거나 손상이 전혀 없다는 뜻은 아니다.

Packed는 전체 성능이 올라도 C+ 손상이 컸다.잘못된 문서에 강한 것과 올바른 문서를 지키는 것은 다르다.

Always: 모든 입력에 같은 Steering 적용. Routing: 개입을 선택. Packed: 두 답변 분기를 비교.
Routing은 대상 데이터의 학습 라벨을 사용하고, Packed는 대상 라벨 없이 평가했다. 서로 다른 조건이므로 최종 우열로 해석하지 않는다.
C+ 비열등 기준: 변화량의 95% CI 하한 > −2%p. Routing의 하한은 −0.60%p. 신뢰구간은 질문 단위 bootstrap 2,000회.
