### 💡 논의 내용

**1. 생성 토큰 길이 (48 → 192)**
- 48 토큰에서는 정답이 포함된 부분이 잘리는 비율이 약 40%로 매우 높았음
- 192 토큰으로 늘리자 절단율이 크게 감소
- 48 토큰과 192 토큰 출력의 앞부분 문자열을 비교한 결과 내용이 크게 달라지지는 않았고, 단순히 길이가 짧아 잘린 것으로 확인
- 교수님: 기존 논문들이 정한 기준이 있는지 먼저 확인해야 함. 다르면 비교 대상 논문들도 다시 돌려야 하는 문제가 생김

**2. 채점 프로토콜**
- Exact match 방식은 골드 단어가 포함되기만 하면 정답 처리되어, 의미상 틀린 답도 맞다고 채점되는 문제가 있었음
- 첫 문장 기준, 마지막 문장 기준, EM 세 가지를 모두 시도했으나 전부 성능이 좋지 않았음
- 수동 채점을 3명이 각 136건씩 나누어 진행하고, 중복 문항을 넣어 채점자 간 일치도를 확인한 결과 거의 동일하게 채점되어 일관성은 확보
- 박은주 학생: 보통은 프롬프트에서 single word로 답하도록 지시하고 채점함
- 교수님: 데이터셋이 아니라 메소드 쪽에서 답변 형식을 지정하는 방식이며, 심플한 벤치마크로 갈 거라면 첫 단어만 보는 방식도 가능

**3. 시그마 산정 방식 (grand STD vs projection STD)**
- grand STD는 좌표 기반, projection STD는 w 방향으로 히든 스테이트를 투영해 얻은 값
- w를 온라인 업데이트하다 보니 w가 바뀐 영향인지 시그마가 바뀐 영향인지 구분되지 않는 문제
- 교수님: w가 움직이는 타겟인데 거기에 투영하는 것은 움직이는 해시계와 같음. 값이 이중으로 흔들릴 수밖에 없음
- 교수님: 두 방식을 다 돌려보기 전에, 애초에 w 방향으로 투영하는 것이 어떤 의미인지를 먼저 규명해야 함. 그렇지 않으면 결과를 봐도 해석이 안 될 가능성이 큼

**4. 스티어링 주입 시점 (P9 vs P10)**
- P9: 컨텍스트를 읽는 시점부터 계속 주입
- P10: 답변 직전 마지막 토큰에서 한 번만 주입
- 박은주 학생: 마지막 토큰만 건드리면 오토리그레시브 특성상 생성할 때마다 앞 토큰이 바뀌어 불안정했던 경험이 있음
- 교수님: 기존 할루시네이션 연구를 보면 답변 표현이 아니라 이해 단계가 문제인 경우가 많으므로, 이해 단계부터 개입하는 P9 쪽이 더 플로저블함
- 교수님: 논문 리뷰에서 반드시 나올 질문이므로 선제적으로 비교 실험을 해두는 편이 좋음

**5. 온라인 시그마 계산 및 층 비교 재계산**
- 같은 레이어 안에서는 밀기 전 값을 사용하는 것이 맞았으나, 레이어 델타가 누적되어 오염되는 문제가 있어 제거 후 재실행
- 개입 붕괴율이 54%로 줄었으나 여전히 높아 추가 실험 필요
- 수동 채점을 반영해 재계산한 결과, 중후반 레이어 개입이 초반 레이어보다 유의미하게 좋았음

**6. w 추정에 필요한 데이터 수 (n)**
- n을 30에서 150까지 늘려가며 확인한 결과, n이 클수록 재현성이 높아지고 결과가 안정적임
- 데이터가 쌓일수록 안정되는 것은 당연한 결과이므로, 최소 몇 개가 필요한지를 밝히는 것이 관건
- 교수님: n을 100~200 정도로 가정하는 것도 가능하지만, 데이터를 모으는 비용에 대한 설득이 필요함. 적은 데이터로 분포를 가정해 빠르게 추정하는 선행 연구들을 조사해볼 것

**7. K+/K- 및 C 라벨링, 골드 프리 여부**
- K+/C- 방향으로 무조건 밀었을 때 K-/C- 케이스에서 정확도가 훼손되는 경향이 나타남 → 사전 필터링 필요
- Excel 방향보다 Retain 방향이 상대적으로 안전한 결과
- 기존 K+/K- 라벨링이 48 토큰 기준이어서 현재 세팅과 불일치 → 192 토큰으로 재라벨링 필요
- 골드 프리 관련: 클로즈드북 답변과 골드를 비교해 셀을 나누므로 완전한 골드 프리라고 보기 어렵다는 의문 제기
- 교수님: w를 뽑는 셀을 고를 때 골드가 쓰이는 구조. 인퍼런스를 한 번만에 끝낼 수 있는지, 두 번 왕복해야 하는지를 꼼꼼히 비교해 확정할 것. 한 번에 되면 가장 좋지만, 성능이 더 좋다면 두 번도 문제없음

**8. 자동 채점기**
- LLaMA 기반 자동 채점기 시도했으나 실패
- 교수님: GPT API 등을 쓸 수는 있으나 실험마다 비용이 발생. 답변 형식을 한정해 채점을 확실하게 하는 방향이 현실적임
